# Plan: Automatización de Renovación de Contratos con Incremento IPC

## Resumen Ejecutivo

Este documento presenta el análisis técnico completo y la cotización profesional para la automatización del proceso de renovación de contratos de arrendamiento con aplicación del incremento por IPC, incluyendo la sincronización de información entre módulos y la notificación de contratos renovados.

---

## 1. Análisis Técnico

### 1.1 Arquitectura Actual del Proceso de Renovación

**Stack Tecnológico:**
- Backend: Python con Clean Architecture (4 capas)
- Frontend: Reflex (Python full-stack framework)
- Base de datos: PostgreSQL (producción) / SQLite (desarrollo)
- Patrón: Repository Pattern + Service Layer + State (Reflex)

**Capas Arquitectónicas:**

```
src/
  dominio/          → Entidades, constantes, servicios de dominio, interfaces
  aplicacion/       → Servicios de orquestación, decorators, esquemas
  infraestructura/  → Repositorios PostgreSQL, cache, servicios externos
  presentacion_reflex/ → UI Reflex (pages, components, state)
```

**Flujo Actual de Renovación (Manual):**

```
UI (modal_renovacion_contrato)
  → ContratosState.execute_renewal()
    → ServicioContratos.renovar_arrendamiento()
      → ServicioContratoArrendamiento._ejecutar_renovacion_arrendamiento()
        1. Validar contrato ACTIVO
        2. Calcular nueva fecha_fin: sumar_meses(fecha_fin_actual, duracion)
        3. Si duracion >= 12 meses: aplicar IPC (obtener_ultimo() → calcular_incremento)
        4. Registrar RenovacionContrato en RENOVACIONES_CONTRATOS
        5. Actualizar contrato: fecha_fin, canon, fecha_renovacion
        6. Cascada: Propiedad.canon_arrendamiento_estimado + Mandato.canon_mandato/fecha_fin
```

**Gap Identificado:**
- No existe proceso automático (batch)
- No hay sincronización con Recaudos ni Liquidaciones de Propietarios
- No existe modal de notificación de contratos renovados

### 1.4 Flujo de Actualización de Datos

**Renovación Actual (parcial):**
1. ✅ Actualiza CONTRATOS_ARRENDAMIENTOS (fecha_fin, canon, fecha_renovacion)
2. ✅ Actualiza PROPIEDADES (canon_arrendamiento_estimado)
3. ✅ Actualiza CONTRATOS_MANDATOS (canon_mandato, fecha_fin)
4. ✅ Registra en RENOVACIONES_CONTRATOS
5. ❌ NO actualiza RECAUDOS (conceptos Canon en períodos futuros)
6. ❌ NO actualiza LIQUIDACIONES (canon_bruto en períodos futuros)

### 1.8 Riesgos Técnicos

| Riesgo | Probabilidad | Impacto | Mitigación |
|--------|--------------|---------|------------|
| Inconsistencia en cascada de actualización | Media | Alto | Transacciones DB, rollback en caso de error |
| Race condition en renovación batch | Baja | Alto | Locking pessimista SELECT FOR UPDATE |
| Pérdida de datos históricos | Baja | Crítico | Actualizar SOLO períodos futuros, audit trail |
| Rendimiento en大量 contratos | Media | Medio | Procesamiento por lotes, índices DB |
| Compatibilidad con datos existentes | Media | Alto | Migración de datos, validación previa |

### 1.9 Estrategia de Consistencia Transaccional

```python
# Patrón de transacción para renovación automática
with db.transaccion():
    # 1. Bloquear contratos a renovar (SELECT FOR UPDATE)
    contratos = repo.obtener_contratos_para_renovar(fecha_limite)
    
    for contrato in contratos:
        # 2. Calcular nueva fecha y canon
        nueva_fecha = sumar_meses(contrato.fecha_fin, contrato.duracion)
        nuevo_canon, ipc = calcular_incremento_ipc(contrato.canon)
        
        # 3. Actualizar contrato
        contrato.fecha_fin = nueva_fecha
        contrato.canon = nuevo_canon
        repo.actualizar(contrato)
        
        # 4. Registrar renovación
        repo_renovacion.crear(renovacion_record)
        
        # 5. Cascada: Propiedad
        repo_propiedad.actualizar_canon(contrato.id_propiedad, nuevo_canon)
        
        # 6. Cascada: Mandato
        repo_mandato.actualizar_canon_fecha(contrato.id_contrato_m, nuevo_canon, nueva_fecha)
        
        # 7. Cascada: Recaudos (períodos futuros)
        repo_recaudo.actualizar_canon_por_contrato(
            contrato.id_contrato_a, nuevo_canon, fecha_inicio_renovacion
        )
        
        # 8. Cascada: Liquidaciones (períodos futuros)
        repo_liquidacion.actualizar_canon_por_contrato(
            contrato.id_contrato_m, nuevo_canon, fecha_inicio_renovacion
        )
```

### 1.10 Estrategia de Auditoría y Trazabilidad

- Tabla `RENOVACIONES_CONTRATOS` registra cada renovación con:
  - `TIPO_RENOVACION`: MANUAL o AUTOMATICA
  - `FECHA_RENOVACION`: Timestamp exacto
  - `CREATED_BY`: Usuario o 'SISTEMA_AUTOMATICO'
- Log de auditoría para cada actualización en cascada
- Snapshot de valores anteriores antes de la actualización

### 1.11 Compatibilidad con Procesos Existentes

- La renovación manual existente NO se modifica (se extiende)
- El proceso batch es OPCIONAL y se ejecuta bajo demanda
- Los períodos anteriores NUNCA se modifican
- El sistema existente de notificaciones se reutiliza

### 2.3 Flujo de Renovación Automática Detallado

```
PASO 1: IDENTIFICACIÓN
├── Query: SELECT * FROM CONTRATOS_ARRENDAMIENTOS 
│   WHERE ESTADO_CONTRATO_A = 'ACTIVO'
│   AND FECHA_FIN_CONTRATO_A <= CURRENT_DATE + INTERVAL '30 days'
│   AND RENOVACION_AUTOMATICA_PROCESADA = FALSE
│
PASO 2: VALIDACIÓN POR CONTRATO
├── Verificar duración >= 12 meses
├── Verificar que no tenga renovación pendiente
├── Obtener último IPC registrado
│
PASO 3: CÁLCULO
├── nueva_fecha_fin = sumar_meses(fecha_fin_actual, duracion)
├── nuevo_canon = canon_actual * (1 + ipc/100)
├── redondear a miles (opcional)
│
PASO 4: ACTUALIZACIÓN EN TRANSACCIÓN
├── BEGIN TRANSACTION
│   ├── UPDATE CONTRATOS_ARRENDAMIENTOS SET ...
│   ├── INSERT INTO RENOVACIONES_CONTRATOS ...
│   ├── UPDATE PROPIEDADES SET canon_arrendamiento_estimado = ...
│   ├── UPDATE CONTRATOS_MANDATOS SET canon_mandato = ..., fecha_fin = ...
│   ├── UPDATE RECAUDO_CONCEPTOS SET valor = ... 
│   │   WHERE id_recaudo IN (SELECT id_recaudo FROM RECAUDOS WHERE id_contrato_a = ...)
│   │   AND tipo_concepto = 'Canon' AND periodo >= fecha_inicio_renovacion
│   ├── UPDATE LIQUIDACIONES SET canon_bruto = ..., comision_monto = ..., ...
│   │   WHERE id_contrato_m = ... AND periodo >= fecha_inicio_renovacion
│   └── COMMIT
│
PASO 5: RECOLECCIÓN DE RESULTADOS
├── Para cada contrato renovado:
│   ├── id_contrato
│   ├── propiedad_direccion
│   ├── arrendatario_nombre
│   ├── canon_anterior
│   ├── canon_nuevo
│   ├── valor_incremento
│   ├── porcentaje_ipc
│   ├── fecha_renovacion
│   └── periodo_vigencia
│
PASO 6: NOTIFICACIÓN
├── Almacenar resultados en ContratosState
├── Mostrar modal al ingresar al módulo
└── Permitir al usuario validar
```
