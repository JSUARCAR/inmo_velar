# Plan: Fix WebSocket "Invalid websocket upgrade" en Railway

## Problema

Caddy rechaza conexiones WebSocket porque no configura `flush_interval` para streaming. Reflex usa WebSocket para sincronizar el estado del frontend con el backend Python. Cuando Caddy recibe la respuesta HTTP 101 (Switching Protocols), la bufferiza por defecto en lugar de transmitirla inmediatamente, causando que el handshake falle.

## Causa raíz

En `entrypoint.sh` líneas 51-56, el bloque `reverse_proxy` tiene los headers `Upgrade` y `Connection` correctos, pero falta:
1. **`flush_interval -1`** — necesario para streaming WebSocket (bufferiza por defecto)
2. **`X-Forwarded-Proto https`** — Railway termina TLS externamente, el backend ve HTTP plano

## Cambio requerido

**Archivo:** `entrypoint.sh` (líneas 51-56)

**Bloque actual:**
```bash
handle @backend {
    reverse_proxy localhost:8081 {
        header_up Upgrade {http.request.Upgrade}
        header_up Connection {http.request.Connection}
    }
}
```

**Bloque corregido:**
```bash
handle @backend {
    reverse_proxy localhost:8081 {
        header_up Upgrade {http.request.Upgrade}
        header_up Connection {http.request.Connection}
        header_up X-Forwarded-Proto https
        flush_interval -1
    }
}
```

### Cambios

| Línea | Adición | Propósito |
|-------|---------|-----------|
| nueva | `header_up X-Forwarded-Proto https` | Indica al backend que la conexión original es HTTPS (Railway termina TLS) |
| nueva | `flush_interval -1` | Desactiva buffering de Caddy para respuestas streaming (WebSocket) |
