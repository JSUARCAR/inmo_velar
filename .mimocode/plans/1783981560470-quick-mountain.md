# Plan: KPIs Liquidaciones & Recaudos — Análisis Técnico + Cotización Empresarial

> **Proyecto:** Sistema Velar — Inmobiliaria Velar SAS
> **Fecha:** 2026-07-13
> **Versión:** 1.0
> **Alcance:** Diseño e implementación de KPIs para módulos de Liquidaciones y Recaudos

---

## 1. Resumen Ejecutivo

Este documento presenta el análisis de ingeniería inversa de los módulos de **Liquidaciones** y **Recaudos** del Sistema Velar, junto con el diseño, estimación y cotización para la implementación de paneles KPI (Key Performance Indicators) en ambos módulos.

Los KPIs permitirán a los usuarios analizar la información financiera y operativa con métricas clave: Período, Ciclo Operativo, Neto a Pagar/Valor, Estado y Método de Pago, facilitando la toma de decisiones en tiempo real.

#### 2.1.2 Modelo de Datos — Tabla LIQUIDACIONES

```
ID_LIQUIDACION (PK, AUTO)
ID_CONTRATO_M (FK → CONTRATOS_MANDATOS)
PERIODO (TEXT, YYYY-MM)
FECHA_GENERACION (TEXT)

-- Ingresos
CANON_BRUTO (INTEGER)
OTROS_INGRESOS (INTEGER, default 0)
TOTAL_INGRESOS (INTEGER)

-- Egresos
COMISION_PORCENTAJE (INTEGER, base 10000)
COMISION_MONTO (INTEGER)
IVA_COMISION (INTEGER)
IMPUESTO_4X1000 (INTEGER, forzado a 0)
GASTOS_ADMINISTRACION (INTEGER, default 0)
GASTOS_SERVICIOS (INTEGER, default 0)
GASTOS_REPARACIONES (INTEGER, default 0)
VALOR_INCIDENTES (INTEGER, default 0)
PAGO_PREDIAL (INTEGER, default 0)
SEGURO_MONTO (INTEGER, forzado a 0)
OTROS_EGRESOS (INTEGER, default 0)
TOTAL_EGRESOS (INTEGER)

-- Resultado
NETO_A_PAGAR (INTEGER)

-- Estado
ESTADO_LIQUIDACION (TEXT: 'En Proceso'|'Aprobada'|'Pagada'|'Cancelada')

-- Pago
FECHA_PAGO, METODO_PAGO, REFERENCIA_PAGO

-- Auditoría
CREATED_AT, CREATED_BY, UPDATED_AT, UPDATED_BY
```

**Fórmula de cálculo:**
```
total_ingresos = canon_bruto + otros_ingresos
total_egresos = comision_monto + iva_comision + gastos_admin + gastos_serv + gastos_rep + pago_predial + otros_egresos
neto_a_pagar = total_ingresos - total_egresos - valor_incidentes
```

#### 2.1.3 Ciclo Operativo

El Ciclo Operativo (Grupo) **no se almacena directamente** en la tabla LIQUIDACIONES. Se deriva mediante la cadena:

```
LIQUIDACIONES → ID_CONTRATO_M → CONTRATOS_MANDATOS.GRUPO_OPERATIVO
```

Valores posibles: Grupo 1, Grupo 2, Grupo 3, Grupo 4, Grupo 5.

#### 2.1.4 Estados de Liquidación

| Estado | Descripción | Transiciones permitidas |
|--------|-------------|------------------------|
| En Proceso | Creada, editable | → Aprobada, → Cancelada, → Eliminada |
| Aprobada | Lista para pago | → Pagada, → En Proceso (revertir) |
| Pagada | Pago registrado | → ReversarPago (vuelve a Aprobada) |
| Cancelada | Anulada | Estado terminal |

#### 2.1.5 Filtros Existentes

- **Período:** Select con últimos 24 meses (YYYY-MM)
- **Estado:** Todos / En Proceso / Aprobada / Pagada / Cancelada
- **Ciclo Operativo:** Todos / 1-5
- **Asesor:** Todos + lista dinámica
- **Columna Financiera:** Rango (min/max) para 8 columnas financieras
- **Búsqueda:** Texto libre
- **Vista Agrupada:** Toggle individual vs. por propietario

#### 2.1.6 Cálculos Clave para KPIs

- **Neto a Pagar:** Campo `neto_a_pagar` directo en BD
- **Total por Período:** Sumatoria de `neto_a_pagar` agrupado por `PERIODO`
- **Total por Ciclo:** Sumatoria de `neto_a_pagar` agrupado por `GRUPO_OPERATIVO`
- **Distribución por Estado:** Conteo agrupado por `ESTADO_LIQUIDACION`
- **Promedio Neto:** `AVG(NETO_A_PAGAR)` por período/ciclo

```

```

#### 2.2.3 Ciclo Operativo en Recaudos

**CRÍTICO:** El campo Ciclo Operativo **NO existe** en la tabla RECAUDOS. Se obtiene indirectamente mediante:

```
RECAUDOS → ID_CONTRATO_A → CONTRATOS_ARRENDAMIENTOS → ID_PROPIEDAD → PROPIEDADES → CONTRATOS_MANDATOS → GRUPO_OPERATIVO
```

Esta cadena de 4 saltos es una complejidad técnica conocida (documentada en MEMORY.md).

#### 2.2.4 Estados de Recaudo

| Estado | Descripción | Acciones disponibles |
|--------|-------------|---------------------|
| Pendiente | Pago registrado, no aplicado | Editar, Aplicar, Eliminar |
| Aplicado | Pago aplicado a cuenta | Reversar |
| Reversado | Pago anulado | Estado terminal |
| Vencido | Pago no aplicado a tiempo | Editar, Aplicar, Eliminar |

#### 2.2.5 Métodos de Pago

| Método | Requiere referencia |
|--------|-------------------|
| Efectivo | No |
| Transferencia | Sí |
| PSE | Sí |
| Consignación | Sí |

#### 2.2.6 Filtros Existentes

- **Estado:** Todos / Pendiente / Vencido / Aplicado / Reversado
- **Pago Contrato:** Multi-select (1-31, día del mes)
- **Ciclo Operativo:** Multi-select (Grupos dinámicos)
- **Propiedad:** Multi-select (direcciones)
- **Fechas:** Desde / Hasta (date picker)
- **Búsqueda:** Texto libre (propiedad, arrendatario, matrícula)

#### 2.2.7 Cálculos Clave para KPIs

- **Total Recaudado:** Sumatoria de `VALOR_TOTAL` donde `ESTADO_RECAUDO = 'Aplicado'`
- **Total por Período:** Sumatoria agrupada por período de conceptos
- **Total por Método de Pago:** Sumatoria agrupada por `METODO_PAGO`
- **Total por Ciclo:** Sumatoria vía cadena de relación (4 saltos)
- **Distribución por Estado:** Conteo agrupado por `ESTADO_RECAUDO`
- **Promedio Recaudo:** `AVG(VALOR_TOTAL)` por período/ciclo

## 3. Diseño de la Solución — KPIs Propuestos

| **Promedio Neto** | Promedio | `AVG(NETO_A_PAGAR)` filtrado | Moneda, por liquidación |

| Columna | Descripción |
|---------|-------------|
| Período | YYYY-MM |
| Ciclo Operativo | Grupo 1-5 |
| Total Neto a Pagar | Sumatoria de neto_a_pagar del grupo período+ciclo |
| Cantidad Liquidaciones | Conteo |
| En Proceso | Conteo por estado |
| Aprobada | Conteo por estado |
| Pagada | Conteo por estado |
| Cancelada | Conteo por estado |

#### Filtros KPI

- **Período:** Rango (desde/hasta) — hereda los 24 meses existentes
- **Ciclo Operativo:** Multi-select (Grupo 1-5)
- **Estado:** Multi-select (En Proceso / Aprobada / Pagada / Cancelada)

| KPI | Tipo | Fuente de datos | Visualización |
